# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`p2pwatch` continuously surveils the eMule network (eD2k + Kad, via an aMule client driven over amuleapi, its REST surface) to recover lost-media episodes of the French dub of *Keroro mission Titar* (aired 2008 on Teletoon), cataloguing all available metadata along the way.

It is a **virtual uv workspace** with eight packages: `packages/crawler/` (package `p2pwatch`, dist `p2pwatch`), `packages/amule/` (package `p2pwatch_amule`, dist `p2pwatch-amule`, stdlib only, the aMule container's boot step and port-sync), `packages/matching/` (package `catalog_matching`, dist `catalog-matching`, shared domain), `packages/pytest_settings/` (package `pytest_settings`, dist `pytest-settings`, the pytest settings every package's tests share), and four dev/CI tooling packages never shipped in a prod image: `packages/vex_checks/` (package `vex_checks`, dist `vex-checks`, reads `security/*.vex.openvex.json` to keep our OpenVEX claims honest), `packages/template_checks/` (package `template_checks`, dist `template-checks`, keeps the webui's Jinja templates logic-free: `poe template-check`, and lists the names they read for `poe dead-code-check`), `packages/coverage_checks/` (package `coverage_checks`, dist `coverage-checks`, checks that each module is covered by its own tests, the test files mirroring `src`: run by `poe test`) and `packages/amule_bump/` (package `amule_bump`, dist `amule-bump`, stdlib only, run by `.github/workflows/amule-bump.yml` to bump the aMule pin and write the PR body). The crawler package `p2pwatch` also contains the in-process webui subpackage `p2pwatch.adapters.driving.webui` (read-only catalog viewer + light runtime controls + read-only SQL console), served on its own thread by `python -m p2pwatch crawl`. A node is **two images, two containers**: the core `p2pwatch` (the crawler and its webui only, no s6, run as `PUID:PGID`, restarted by Docker) and `p2pwatch-amule`, compose service `ed2k`, where s6 supervises amuled (which starts amuleapi itself) and port-sync. The core reaches amuleapi at `ed2k:4711` in both compose variants (see the confinement invariant below).

## Design invariants (do not violate)

- **The catalog records files and, where a protocol publishes one, the pseudonymous identifier of the source that shared them**, so that a researcher can recognise a recurring sharer and contact a possible archivist. It never stores a peer's network address (IP, port, country), and never links identifiers across networks.
- **The crawler never reads downloaded bytes, and never touches the filesystem of the output directory.** The core mounts the output directory read-only, for the disk floor's `statvfs` only. One deliberate exception, in the aMule container: its boot step (`python -m p2pwatch_amule boot`) creates the mount points `/downloads/incoming` and `/downloads/temp` and chowns them, not recursively, to `PUID:PGID`, so that amuled, running as `amule`, can write there. It runs once as root before s6 starts anything, the crawler never imports it, and it never lists, opens or changes what the mounts contain. It lives in `packages/amule/`, under the same gate (mypy, coverage, the VEX source claims check).
- **`docs/` is the Zensical root and is published in full**: every `.md` under it becomes a page on https://mission-titar.github.io/p2pwatch/, because Zensical builds every file in `docs_dir` whether or not the nav references it. Anything that should not be published goes in `agents/` (specs, plans, handoffs, reference notes), never in `docs/`. The site is built by `uv run poe docs-build`, which passes `--strict` so a broken link or a dead anchor fails the build instead of shipping silently.
- **Package boundary:** which package imports which is the hexagon rule's (Hard rules, "Clean / Hexagonal"). `vex_checks`, `template_checks`, `coverage_checks` and `amule_bump` are dev/CI tooling, never installed in the prod image. `pytest_settings` is shared test configuration, not a hexagon: one module, declared in `tach.toml`, holding what every package's pytest run applies (the root's `dev` group installs it, its `pytest11` entry point loads it), outside vulture's scope like the tests, and never installed in the prod image.
- **Two run modes, one topology:** `download.enabled: true` (the shipped default) wires the download loop live; `download.enabled: false` or an absent `download:` section is crawl-only. This is a **config flag**, not two ways of assembling the stack: both compose variants start every service unconditionally, and there is no compose profile anywhere.
- **The merge** (`python -m p2pwatch merge`) is never called by the crawl and writes only to its destination: a new file (`--output`), or the source named by `--into`, which `open_catalog` first migrates in place to the current schema.
- **`deploy/` is the operator-owned single source of truth for config**: `deploy/crawler.yml` / `deploy/matcher.yml` / `deploy/targets.yml` stay editable-by-operator deployment config, next to the compose files that mount them; it is **forbidden to canonicalize them as code artifacts** (package data, inline policy dicts, or duplicate test fixtures that shadow them). Every consumer *derives from* `deploy/`, never the reverse: the matcher policy has exactly ONE copy (`deploy/matcher.yml`), read by the matching golden corpus + engine unit tests via `parents[N]`: a test-time path coupling to `deploy/`, deliberately accepted (test-only, not an import; the code DAG is unchanged). Do not reintroduce a `canonical_config.yaml` fixture or an inline `_CANONICAL_RAW` policy dict.
- **Boundary discipline** absorb failures from external I/O (an apprise notifier, a call to the daemon → degrade), but let in-process 100%-tested code crash loudly (a `PrometheusMetricsRecorder` failure is a bug, not a transient).
- **A store has no clock**: a SQLite store, or `InMemoryStatusReadingStore`, stores the instants it is given and decides no wait; its caller reads the clock right before each write (`wall_clock.now()` for a row). An adapter other than a store may hold a `MonotonicClock` for a guard of its own I/O: the amuleapi client's start pacing and search deadlines, the SQL console's query budget.

## Commands

The gate lives in `pyproject.toml` under `[tool.poe.tasks]` (poethepoet) as the single source of truth: the pre-push hook and CI both call it. `uv run poe` lists every task with its `help`.

```bash
uv sync --dev        # install (scripts/setup-dev.sh also installs the pre-push hook)
uv run poe check     # THE FULL GATE (lint-all + test): the pre-push hook and CI run exactly this
uv run poe fix       # auto-fix everything mechanical: ruff --fix + ruff format + sqlfluff fix
```

Gate sub-tasks, runnable in isolation: `lint` · `format-check` · `dependency-check` · `code-pattern-check` · `architecture-check` · `dead-code-check` · `type-check` · `pyrefly-check` · `sql-lint` · `template-check` (grouped as **`lint-all`**; `dependency-check` runs deptry twice per package, `src` against the runtime dependencies, then `src` and `tests` with the `dev` group too; `code-pattern-check` runs the rule tests of `ast-grep-tests/`, then the ast-grep rules of `ast-grep-rules/` (their shared matcher in `ast-grep-utils/`), which `sgconfig.yml` names; `architecture-check` runs `tach check`, then `tach check-external`, over `tach.toml`; `dead-code-check` runs vulture once over every package's `src` but `pytest_settings`', never the tests, ignoring the attributes the templates read, which poe passes it from `_template-attributes`, so a bare `vulture` reports every view field; `type-check` runs mypy once per package, over its `src` and `tests`, so a `py.typed` package's errors show only in its own run; `pyrefly-check` runs pyrefly once per package, from the package's own `[tool.pyrefly]`, on import errors only), and **`test`** (runs each package's suite in its own process, so per-package coverage stays isolated, and the tests of the source rules in `packages/vex_checks/ast-grep/`, then `_unit-coverage-check`, which reads the per-test contexts each run records, `--cov-context=test`, and which poe runs only inside `test`, so it never reads a stale or partial `.coverage`). Fixers: `lint-fix` · `format-fix` · `sql-fix` (grouped as **`fix`**).

**Before hand-fixing lint / formatting / SQL, run `uv run poe fix`**: don't spend turns rewriting by hand what a fixer applies mechanically; review its diff instead.

**The gate is PER PACKAGE** (`cd packages/<pkg> && uv run pytest`). The intent: each package owns its own pytest config and 100 % branch coverage in isolation: a root run would mix coverage data across packages and break the per-package threshold. A bare `uv run pytest` from the repo root is also blocked mechanically (the root has no `[tool.pytest.ini_options]` and a root `conftest.py` sets `collect_ignore_glob = ["packages/*"]` → exit 5 with zero collected). Tooling split: `[tool.ruff]` at root spans all eight packages, `[tool.vulture]` all but `pytest_settings`, `tach.toml` all, and `[tool.mypy]` at root holds the settings every package's own run reads; `[tool.pytest]` / `[tool.coverage]` / `[tool.coverage_checks]` / `[tool.sqlfluff]` / `[tool.deptry]` are per-package, and so are the test dependencies, in each package's `dev` group (the root's holds only the workspace's tools, `pytest-settings` among them); one root `uv.lock`. Every `tests/` directory is a package (data directories such as matching's `tests/fixtures` aside), so a test module is `tests.<path>`, imports its helpers as such (`from tests.fakes.adapters.driven.fake_upstream_client import FakeUpstreamClient`), and may share its basename with a test module of another directory or package. The tests mirror `src`: `src/<pkg>/a/b.py` is tested by `tests/a/test_b.py`, and by `tests/a/test_b_<aspect>.py` when its tests split (a test file belongs to the longest module name it extends; `__main__.py` and `__init__.py` take `test_main` and `test_init`); `_unit-coverage-check` fails on a test file that tests no module, unless its package lists it in `[tool.coverage_checks] tests_without_unit` with what it tests. A double lives in its package's `tests/fakes` (`from tests.fakes.adapters.driven.fake_time import FakeTime`, Hard rules), never in a test module another imports; a shared helper lives in `tests/support/`, and a port's contract in `tests/contracts/` (Hard rules). The run of every package that has them measures all three (`--cov=tests`, its test files and conftests omitted), so support code no test runs fails its package's gate. Deployment artifacts live under `deploy/` (`compose.yml`, the three config files, `.env.example`, `data/`, and `ed2k/` with its compose files and state); the smoke stack under `tests/smoke/`.

**Single test** (the package-wide `--cov-fail-under=100` makes a lone test "fail": disable coverage):

```bash
( cd packages/matching && uv run pytest tests/domain/test_engine.py::test_evaluate_real_62a_is_download_via_first_rule_on_62a --no-cov -q )
```

Integration suites (Docker, deselected by default, excluded from coverage) are documented in `docs/contributing/testing.md`. They run locally, Docker Desktop included; only the compose smoke's completion test fails under Docker Desktop (its bind mount keeps SQLite's `-shm` incoherent), and CI is authoritative for it.

## Hard rules (enforced, non-negotiable: do not relax)

- **100% branch coverage on unit tests, per package, and of each module by its own tests**, gated in CI and the pre-push hook (`--cov-fail-under=100`, `branch=true`, and `test`'s `_unit-coverage-check`, where what a module's import runs counts as covered by any test). A package's `tests/fakes`, `tests/support` and `tests/contracts` are measured at 100 % too, their `test_*.py` omitted as everywhere, and left out of `_unit-coverage-check`; a double's own tests sit beside it, in a `test_<double module>.py` listed in `tests_without_unit`, and `tests/contracts` holds none. Integration suites (`api_integration`, `download_integration`, `orchestration_integration`, `compose_integration`) are deselected by the crawler's `addopts` and excluded from coverage measurement: the local gate (`poe check`, the pre-push hook) never runs them, CI's required `validate / gate` check does (`build-and-verify`, on both architectures), and locally they run on demand (see `docs/contributing/testing.md`). Never lower the unit-test threshold; add the missing test (exercise *both* sides of every conditional).
- **Strict TDD**: tests are the spec; write the failing test first, watch it fail, then the minimal implementation. Code review judges the tests first. Every test function is annotated `-> None` with typed params.
- **`mypy --strict`** over **both `src` and `tests`**. **`ruff`** selects `E,F,I,UP,B,SIM,TID251`, line-length **100**.
- **No dynamic attribute access**: `getattr`, `setattr`, `hasattr`, `delattr` and `vars` are banned in `src` and `tests`, and so are `__dict__`, `__getattr__`, `__getattribute__`, `__setattr__`, `__delattr__`, `operator.attrgetter` and `operator.methodcaller`, even as an attribute's or a method's name (`code-pattern-check`, which refuses `__builtins__` and any import of `builtins` too, so `builtins.getattr` cannot be written out). An exception carries `# ast-grep-ignore: no-dynamic-attribute` and its reason.
- **A test sets what it tunes through a parameter, never by patching a module**: process state (`os.environ`, the working directory, the root logger, the temporary directory) is read only by a `__main__.py` and passed down as values; a constant a test tunes is a parameter; a function a test replaces is passed to what calls it, a driven port when the core needs it, a typed `Callable` parameter inside an adapter. The composition passes the real value, never a parameter's default. What is part of an adapter's code (its SQL, its migration scripts, the SQL functions they call) is no parameter: a test that tunes it tests a generic mechanism, which moves apart and receives it, as the migration runner receives its scripts. `code-pattern-check` refuses the `monkeypatch` fixture, `pytest.MonkeyPatch` and `unittest.mock`'s `patch` in every Python file.
- **A parameter object only for values that form a concept** (`Interval`, `FileKey`, `BackoffPolicy`), never a bag of dependencies: a component receives each dependency through its constructor, is split by responsibility, and holds its state in its own attributes (`DownloadCycle` over its four stages, each owning its own state).
- **An adapter receives from the composition what it drives**: a directory or a file, a URL or an address, an executable's path (`AmuleApiClient(host, port, ...)`). An adapter that runs a program receives `run_command`, typed `Callable[..., subprocess.CompletedProcess[str]]` at each site since hexagons share no module, and every call passes `text=True`, which the annotation promises and mypy cannot check. Its unit test hands it a local stand-in (`tmp_path`, a loopback server, a runner that records the commands it is given), the integration suites the real one.
- **The composition builds, `__main__.py` reads the process**: every hexagon's `composition/command_line.py` exposes `build_command_line(...)`, which builds the adapters, the use cases and the command line, the fixed values (an address, a path, an executable, a URL, a width) being its constants and the process resources it uses (`build_opener()`, `TemporaryDirectory()`) its own; `__main__.py` reads the process state (argv, env, cwd, the root logger, the temporary directory), calls `build_command_line(...).run(argv)` and imports nothing else of its package. The composition builds each graph when what it needs exists: at start, in `build_command_line`; during a call, by implementing the driving port that makes that call (`CrawlerComposition`, `BootComposition`, `PortSyncComposition`, `UnitCoverageComposition`).
- **A value taken when the operator sets nothing is the domain's**: a key absent from `crawler.yml`, an environment variable left unset, an option left off the command line. The parser applies the domain's value (`p2pwatch.domain.config_defaults`, `p2pwatch_amule.domain.settings`), never a dataclass field's default nor a literal in an option's `default=` or `set_defaults`, which `code-pattern-check` refuses when written in the call, one behind a name being a review matter (a fixed value no option sets is the composition's); a value a component receives comes from the composition, as the two rules above state.
- **A broken input raises; a problem is a finding on a valid input**: a check that cannot read a file (absent, unreadable, not the format it expects) raises its domain's `BrokenInputError` naming the file, and its command line prints it on one line and returns 1, never a traceback and never a problem of its report (`vex_checks`, `template_checks`, `coverage_checks`, the crawler's `validate-config`).
- **No code only tests reach**: `dead-code-check` reports what no production path uses: delete it with its tests. `vulture_whitelist.py` is a rare exit for a blind tool: first make the call visible to vulture (pass a hook by name, e.g. a function as `BaseHTTPMiddleware(dispatch=...)`); an entry only for a call no rewrite can show, with its reason. A name a template reads needs nothing.
- **Only the clock adapters read the system clock or sleep, asyncio's own timeouts aside**: everything else injects `WallClock` or `MonotonicClock`. `TID251` bans the calls (`datetime.now`, `time.monotonic`, `time.sleep`, `asyncio.sleep`…) outside `SystemWallClock`, `AsyncioMonotonicClock`, `p2pwatch_amule`'s `SystemMonotonicClock`, and every `tests/` tree; it leaves `asyncio.wait_for` and `asyncio.timeout` allowed and cannot see `loop.time()`, all three on the event loop's monotonic time. A yield, `asyncio.sleep(0)`, keeps a `# noqa: TID251`.
- **Clean / Hexagonal** (`agents/specs/2026-10-18-hexagonal-architecture.md`): six hexagons, `p2pwatch` (with `catalog_matching`, its domain ring in a distribution of its own), `p2pwatch_amule`, `vex_checks`, `template_checks`, `coverage_checks` and `amule_bump`, never import one another. A hexagon has four rings, read from the path, `<pkg>/{domain,application,adapters,composition}/`, with `adapters/` split into `driving/` and `driven/`; a root `__main__.py` belongs to the composition. The ring `application/` holds tach's layers `ports/{driving,driven}/`, `use_cases/`, `steps/` and at most one `<x>_lifecycle.py`: a use case is called from outside, through a driving port, with the modules only it calls; a step is a stage of the lifecycle's graph, called only by the lifecycle or another step; the lifecycle is the program from its start to its stop, which the composition runs (`CrawlerLifecycle`, `PortSyncLifecycle`). Code that calls no port goes to `domain/`. Imports point inward (`domain` < `ports` < `use_cases` < `steps` < `lifecycle` < `adapters` < `composition`, tach's layers) and form no cycle; `use_cases/` and `steps/` never import each other nor the lifecycle (tach has no sibling layers, so a step's import of a use case is refused by `use_cases`' `visibility`); an adapter never imports another adapter, a driving adapter depends on driving ports only, a driven adapter on the driven ports it implements or consumes, a use case implements a driving port over driven ports, and every one of them may import its domain.
- **One port per file, named after it** in snake case (`application/ports/driven/catalog_finder.py` holds `CatalogFinder`), beside the types its signatures use; the error types of ports, which both sides use, live in `domain/` (`client_errors.py`). `packages/crawler/tests/test_port_files.py` checks every hexagon's port files.
- **A step is a class, one per module, named after it** in snake case (`application/steps/node_id_resolver.py` holds `NodeIdResolver`), beside the values its signatures use (`BackoffPolicy`, `SearchTask`): its dependencies come at construction, the run's values (`node_id`, a file) at the call (`NodeIdResolver.resolve()`, `CatalogReevaluator.reevaluate_if_policy_changed(node_id)`).
- **Each double in a file of its own, in the ring of what it replaces**: a double of the hexagon's boundary (a port's implementation, a callable an adapter receives, an outside system) lives in its package's `tests/fakes/`, as an adapter for tests, one per file named after it in snake case: a driven port's double, or the one of what an adapter receives (`FakeCommandRunner`), under `adapters/driven/`; a driving port's under `application/use_cases/`, or under `composition/` where the composition implements the port (`FakeCrawlerRunner`); an outside system's (`FakeAmuleApiServer`) at the root. A double implements one port, or one `<Thing>Writer` and `<Thing>Reader` pair, which share one store; a double mixing unrelated ports splits. A record a double returns or keeps (`LoggedLine`) lives in its file. A stand-in for core code that one test module uses (a domain `Matcher`) stays in that module, like a harness, and what is no double lives in `tests/support/`, at the mirror of the module it serves. `packages/crawler/tests/test_fake_files.py` checks every package's doubles.
- **A contract per contracted port, or per Writer/Reader pair**: `<Port>Contract`, or `<Thing>StoreContract` for a pair, an ABC in `tests/contracts/application/ports/driven/<snake case>_contract.py`, at the mirror of the port, whose abstract fixture builds the implementation under test and whose tests state the port's docstrings. A pair's contract types its fixture with a `Protocol` of the pair, named `<Thing>Store`, in the contract's module (tests only, mypy holding each subclass's fixture to it). Each package's `tests/conftest.py` registers `tests.contracts` for pytest's assertion rewriting, which covers only test modules, conftests and plugins: a contract's failing `assert` would otherwise print a bare `AssertionError`.
- **A subclass of the contract per implementation, `Test<Implementation>`**, in the implementation's own test module: a real adapter's test module, or for a fake `tests/fakes/<path of the fake>/test_<fake module>.py`, listed in `tests_without_unit`. A double that breaks its port on purpose is exempt by name, with its reason. `packages/crawler/tests/test_contract_subclasses.py` checks every package's contracts: each covers ports of its own package, a subclass per implementation, each in its implementation's own test module, each abstract fixture defined (pytest silently skips a test class left abstract), no stale exemption.
- **The port is the reference**: a port's docstring is its promise and its contract tests all of it; a behaviour the port leaves unstated enters the docstring when a production consumer relies on it; a double's docstring describes the double against its port, never against another implementation.
- **No I/O in the core**: `domain/`, `application/ports/` and `application/` import only their list in `ast-grep-rules/*-imports.yml` (the pure standard library they use, `rapidfuzz`, `packaging.version` in a domain, first-party packages), `asyncio`, `uuid` and `io` by the names `core-import-names.yml` lists, `pathlib` by `PurePath`, `configparser` in `p2pwatch_amule`'s domain only and `jinja2` in `template_checks`' (each parsing a string, never a file), and call no builtin that does I/O or imports (`core-builtins.yml`); the rules see imports and builtin calls, not what an allowed module's methods do; a use case logs through the `Logger` port, which `StdlibLogger` implements under the name of the module that logs. A module that does I/O goes to an adapter, even if most of it is logic; where that would have the core import an adapter, the imported piece moves into the core. A new import is a new line in its ring's list, never an ignore. `${NAME}` env-var interpolation in `crawler.yml` is resolved by the config adapter before anything reaches the domain: the domain itself never touches env vars.
- **The domain writes plain text; the Markdown is the adapter's**: a notification is a typed value the notifier writes out (`AppriseNotifier` writes a `TierRise`'s title, Markdown body and notify type).
- **A logger is named from the code**: `StdlibLogger(<Class>.__module__)` in the composition, `logging.getLogger(__name__)` in an adapter, never a string literal (`code-pattern-check`, which sees a literal written in the call only: one behind a name, or the wrong class, is a review matter), so a name follows its module when it moves.
- **Every module is declared in `tach.toml`**, one per port file, per adapter, per directory of use cases or of steps and per lifecycle, with exactly the dependencies it uses (`root_module = "forbid"`, `exact`): an undeclared module or edge fails `architecture-check`. A rule broken for now is a dependency declared `deprecated = true`, beside a comment naming its reason and the lot that removes it, never a `# tach-ignore`. `tach check` never sees an import across distributions: `tach check-external` holds each to its package's `pyproject.toml`, and `packages/crawler/tests/test_workspace_dependencies.py` refuses any internal dependency but `p2pwatch` on `catalog-matching`.
- **Python only** (>=3.13). Conventional commits (`feat(domain):`, `fix(domain):`, `test:`, `chore:`, `docs:`).
- **Language: all code is English** (decided 2026-07-02), identifiers AND prose: comments, docstrings, runtime-emitted messages/logs, CI step names, and commit messages. `.gitignore` and `.gitattributes` are the deliberate exceptions (`.gitignore` decided 2026-09-17): operator-facing housekeeping, consistently French. ## Naming

A name lets a reader with partial context tell, from a signature or a call site, what a value holds and what
a function does.

- **One concept, one name, in every layer.** A value keeps its name from where it enters to where it is read.
  An external name (an amuleapi field, a SQLite function's) is translated once, in its mapper or adapter, and
  kept from there. The glossary below fixes the shared words.
- **One name, one concept, within a package**: never a string in one function and a dict under the same
  name in the next.
- **Say what the value is, not its type or its role**: no `what`, `data`, `info`, `item`, `obj`, `result`,
  `value`, `entry`, `payload`; a single letter only inside a one-line comprehension or lambda.
- **A quantity carries its unit unless its type does**: `_seconds`, `_bytes`, `_mib`, `_micros`; a `datetime`
  or a `timedelta` needs none.
- **A boolean reads as a predicate**: `is_tracked`, `has_useful_point`, `clamped`, `enabled`.
- **A function says what it returns or does, side effects included**:
  `reevaluate_if_policy_changed`, `rejudge`. A class names what one instance is: `FileJudge`, `Cataloguer`.
- **A mapping is `<values>_by_<key>`, a collection the plural of its element.**
- **`latest` is the most recent of a series; `last` only pairs with `first`.**
- **No abbreviation but the glossary's**, units and protocol names (`kbps`, `tcp`, `md4`, `ed2k`) aside.
- **Comments, docstrings and log messages use the code's words.**
- **The most telling word wins over the most widespread one**: an existing name is not a reason to keep it.
- **A port is named after the one who does its action**: `CatalogMerger`, "the one who merges catalogs". A port
  is an ABC its implementers and fakes inherit: `code-pattern-check` refuses a `Protocol` base in every package's
  `src`.
- **`Reader` and `Writer` name ports over our own state only (databases, files, memory)**: such a port is a
  `<Thing>Writer` or a `<Thing>Reader`, never both (both databases, the status readings, the run state, a check's
  input files: `SbomReader`, `TestCoverageReader`), and a `Writer` is always half of a store: its `<Thing>Reader`
  reads what it wrote, and one adapter implements the pair (`test_port_files.py`). A `Writer`'s method starts with
  `record_`, which adds a fact and leaves the earlier ones, or `set_`, which replaces a current value; a `Reader`'s
  says what it gives back: `read_` a value, `iter_` an iterator, `is_` or `has_` a predicate, `wait_until_` a state
  reached (`code-pattern-check` holds both). A domain object carries who produced it, so a `Writer` takes the object
  only (`record_observation(observation)`, `record_decision(dated_decision)`, `record_points(points)`), and an
  event that notifies carries its `node_id`; `node_id` is a parameter only as a read's filter.
- **A port to an outside system or a service keeps a capability name**: `DownloadClient`, `MonotonicClock`,
  `Logger`, `UpstreamClient`; a port handing an output to an outside consumer is named after what it does
  (`CodeScanningReporter`, `PullRequestDrafter`, `BumpAnnouncer`). A later consumer that needs part of a port
  splits it then.
- **A use case is named after its operation**: `ValidateConfig`, `MergeCatalogs`.
- **A driving port returns its response model, named from its use case's verb** and defined in the port's file
  (`DescribeNode` returns a `NodeDescription`); a driven read port returns domain types only. The webui renders a
  response model through `<Thing>Display` view models.
- **A check returns a report**: a `<Thing>Report` response model with a `problems` field (`ImageClaimsReport`),
  which the command line prints; asked for SARIF, the use case writes them through its driven port instead.
- **An adapter is named by the system, the thing and the role**: `SqliteObservationStore`,
  `GluetunForwardedPortClient`. The system is what would need another adapter if replaced: a service or a
  database (`AmuleApi`, `Github`, `Sqlite`, `S6`), a format's producer (`Syft`, `CoveragePy`, `OpenVex`), the OS
  beyond reading and writing a file (`Posix`: accounts, ownership, signals), else `Filesystem`; never a syntax
  (`Json`, `Yaml`). A brand keeps its own words' capitals (`Github` is one word, `AmuleApi` two), so its snake
  case follows them (`github`, `amule_api`). A module is the name only when it is the system:
  `ShutilFreeSpaceMeter`, `StdlibLogger`, `ArgparseCommandLine`, `RandomJitterGenerator`.
- **A test double is `Fake` and what it replaces**: `FakeAmuleApiServer`, `FakeSearchClient`; the one of a
  `<Thing>Writer` and `<Thing>Reader` pair is a store, `Fake<Thing>Store` (`FakeTrackedDownloadStore`).

## Gotchas

**Matching engine (stdlib `re`, `re.ASCII`):**
- Regex tokens compile with `re.compile(pattern, re.ASCII)` (`matchers.py`, `validation.py`). `re.ASCII` keeps `\b \d \s \w` ASCII: matching the pre-2026-07-03 RE2 default the existing policy relies on (`fold()` does not reduce non-Latin scripts to ASCII). Case-insensitivity is a leading `(?i)` prefix (not a flag arg). An invalid pattern raises **`re.error`** (caught in `validation.py` → `MatchingConfigError` "not compilable").
- Coverage idioms: an `@abstractmethod`'s body is its docstring alone (a `...` or `pass` under it is a line no test runs). A `case _: assert_never(x)` arm (the "unreachable default" of a `match` over a closed tagged-union) needs `# pragma: no cover` because it is unreachable by design but the branch counter doesn't know that.
- Don't validate config order-dependently (parse pass = structural; graph pass = full table). Recursive validators need an explicit depth guard → a clean `DepthExceededError`, not `RecursionError` (which is a Python runtime artifact, not a domain error).

**Coverage by own tests (`_unit-coverage-check`):**
- **A body the process runs once is credited to one test at most.** A function called at import is credited to none (pytest-cov records collection under the empty context), so its module's own tests must call it. A `functools.cache`d function, module state initialised lazily, or a session- or module-scoped fixture is credited to whichever test runs it first, so its module's own tests pass or fail on test order and selection: keep such state out of `src`, or have the module's own tests reset it (`cache_clear()`).

**amuleapi / amuled (empirical: facts established by hardware probes / source reading, see `agents/reference/`):**
- *amuleapi = the daemon aMule (the version pinned by `ARG AMULE_VERSION` in `packages/amule/Dockerfile`) ships to expose amuled over `/api/v1/*` REST plus SSE, and to serve aMule's web UI. amuled starts it itself (`[AmuleApi] Enabled=1`) and hands it a one-off EC token; EC is now an internal link between the two, not something we speak.*
- **Every list endpoint silently returns only the first 100 rows.** `limit` defaults to 100 on `/downloads`, `/shared`, `/search/{id}/results` and every other list route, so omitting it returns the first hundred items, not the collection. For `downloads()` that is a silent completion failure on any node with more than a hundred queued or shared files. The adapter keyset-pages on the route's identity column (`sort=hash` + `after=<last hash>` for downloads and shared files, `sort=ecid` + `after=<last ecid>` for a download's clients), never `offset`, because `offset` is a position and a row deleted below the cursor slides one row past the window for good.
- **A `401` is terminal for the session.** amuleapi counts every rejected token per IP (30 in 60 s → a 300 s lockout), so a client that retries a `401` locks itself out. The adapter re-logs in exactly ONCE per request and never loops. Restarting amuleapi, or any password change, invalidates every issued token.
- **`media` on a search result is what the responding server advertised**, never a local probe: it can contradict the file (a `.pdf` reporting a runtime and a video codec is a real observed result), and it is `null` on most global and Kad hits. The key is always present, so test for `null`, not for the key.
- **amuled folds the same file's alternative filenames** into `alternate_names[]` under the most-sourced parent; only parents appear at the top level. The mapper unfolds them into one observation per name, because dropping them loses the descriptive name on a third of the catalog's multi-name hashes.
- amuled moves a finished file to its IncomingDir and flips status to complete **after** the move (no race), so by the time the completion is observable the file is already at its final on-disk path. Completion is the client's **positive signal**, never a byte count: a queue entry with `status == "completed"` (moved, awaiting clear), or a file in `GET /shared` and absent from the queue (completed then cleared). A queued file listed in `/shared` is not complete, since amuled shares partfiles too. Detail: `2026-06-17-amuled-completion-behavior.md`.
- **Two listen ports**: TCP `[eMule] Port` (4662) and UDP `[eMule] UDPPort` (4672, Kad's). The direct variant publishes `4672/udp`, never `4662/udp`; port-sync writes both to the one port a tunnel forwards. amuled reads them only at start, and flushes its whole config when it exits, so `amule.conf` is written only while amuled is down.
- **Neither password has a length minimum** in aMule at the pinned commit (no 12-character rule exists); the boot step refuses only control characters in them.

**Serena and its language server, pyrefly (sections cited from `agents/reference/2026-10-16-python-language-server-bench.md`):**
- **A port method is renamed from the port.** The ports are ABCs, and renamed from a base, pyrefly reaches the overrides; renamed from an override, it never climbs to the base (bench 11).
- **Check each rename's diff before the next one**: renames run back to back can reach a few references each and write some edits at shifted offsets; then `git grep -w` the old name.
- **pyrefly resolves a package's `tests` only through the package's own `[tool.pyrefly]`** (`search-path = ["src", "."]`; its sub-configs cannot change import paths). Without it, `pyrefly check` from the root cannot find `tests.fakes` (23 errors in five packages at lot A's base), and the audit's trial saw a rename from a port miss the overrides in `tests` (9 of 12 sites), while mypy stays green, since a stale override becomes an extra method; `pyrefly-check` fails a package that lacks it (bench 11, lot A's spec D1).
- **Never renamed completely by any server**: a pytest fixture's uses in the test bodies, an attribute only a Jinja template reads, a name inside a string (`__all__` included, under pyrefly) and a `dataclasses.replace` keyword (bench 3.1, 5.7).
- **`.serena/project.yml` pins pyrefly 1.4.0 in `lazy-blocking` mode only in a project Serena trusts** (`trusted_project_path_patterns` in the user's global Serena config). Untrusted, Serena starts its own pyrefly 1.2.0 in the default mode, whose first rename after start is partial (bench 11).
